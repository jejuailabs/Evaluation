# 가치 돋보기 — SaaS 개발 프로젝트

사업을 계획하고, 함께 진행하고, 결과를 보고하는 일을 한곳에서. 일하면서 남긴 기록이 우리 조직의 성과가 됩니다.

**상태: 2026-10-05, 설계 v0.1 + 브라우저 로컬 기반 동작 시제품. 운영 서비스가 아닙니다.**

## 웹페이지 열기

공개 체험 주소: [가치 돋보기 · 우리 조직의 작업실](https://value-lens-workspace.naggu1999.chatgpt.site/)

로그인 없이 화면을 살펴볼 수 있는 별도 체험 사이트입니다. 웹페이지 공개와 자료 공유는 별개입니다. 입력과 업로드는 방문자의 브라우저에만 저장되며 다른 사용자에게 전송되지 않습니다. 실제 조직 공동 작업 서버는 아직 연결하지 않았습니다.

## 이번 기초 구현

- 홈 / 프로젝트 / 자료함 / 보고서의 기본 탐색 구조, 네 가지 색상 테마, 반응형 화면.
- 예시 조직의 두 프로젝트, 프로젝트 추가, 업무 추가·상태 변경, 월별 업무 일정.
- 프로젝트에 파일 등록, 같은 문서의 새 버전 추가, 원본 내려받기. 파일은 이 브라우저의 IndexedDB에만 저장합니다.
- 프로젝트별 예산과 집행 기록, 예정/확정/지급 상태의 구분, 담당자별 조회.
- 목표·예상·확인된 실적의 분리, 증빙을 연결한 실적 입력과 확인, 누적 기준일별 이력.
- 프로젝트 시작일부터 선택 기준일까지의 보고서 스냅샷 생성, 재열람, 독립 HTML 내려받기.
- 도메인 타입, 계산·검증 함수, 상태 변경 함수, 저장 어댑터를 화면과 분리.

**아직 구현하지 않은 것:** 서버 로그인·권한 집행·다중 사용자 협업·조직 생성/초대, AI 분석, OCR/HWPX 내용 추출·원본 편집·서식 재현, 정식 결재, 임의 기간의 정교한 통계, 백업/복구, 외부 연동. 화면의 ‘확인’은 시제품 동작이며 실제 승인 권한이나 감사 보장을 제공하지 않습니다. 파일과 입력값은 다른 기기에서 공유되지 않으며, 브라우저 데이터를 지우면 사라집니다.

기존 `../value-lens`는 공개 랜딩페이지입니다. 이 폴더는 별도 SaaS 체험 사이트의 개발 코드이며 기존 랜딩페이지를 덮어쓰지 않습니다.

## 실행

Node.js 22.21 이상을 기준으로 확인합니다.

```sh
npm ci
npm run dev
```

주소는 `http://127.0.0.1:5174`입니다. 종료 후 다시 실행하면 같은 브라우저에 저장된 작업을 이어갑니다.

이 컴퓨터에는 필요한 패키지를 설치했습니다. Windows에서는 `start-dev.cmd`를 실행해도 개발 서버가 열립니다. 이 프로그램은 로컬 개발용이며 다른 컴퓨터에서 접속하는 공개 주소가 아닙니다.

```sh
npm test
npm run build
```

검증 결과와 미확인 범위는 [검증 기록](qa/verification.md)에 있습니다. 자동 검증 16개와 빌드는 통과했고, 브라우저 다운로드 수신·모바일 최종 캡처에는 도구 제약이 남아 있습니다.

## 코드 구조

```text
docs/                    제품 합의와 개발 기준
src/domain/              데이터 타입, 계산, 변경 규칙, 예시 데이터
src/infrastructure/      로컬 저장, 파일 저장, 보고서 출력
src/features/            홈·프로젝트·자료·예산·성과·보고서 화면
src/ui/                  공통 화면 요소와 색상 규칙
src/App.tsx              내비게이션과 화면 연결
tests/                   집계·예산·증빙·스냅샷 회귀 검증
```

## 다음 개발의 시작점

우선 `docs/05-build-and-acceptance.md`의 B1을 진행합니다. 서비스 연결 시 로컬 전체 상태 저장을 그대로 서버에 보내지 않습니다. 서버가 조직·권한·버전을 검증하는 명령 API와 트랜잭션으로 대체하고, 같은 도메인 검증을 재사용합니다. 저장 어댑터만 바꾸면 운영 서비스가 완성되는 구조라고 해석하면 안 됩니다.

이 시제품의 데이터 모델은 대화를 코드로 검증하는 최소 모델입니다. 전체 운영 모델과 권한·상태 전이 기준은 설계 문서가 기준입니다. 기능 변경 시 코드와 관련 문서의 상태를 같이 갱신합니다.

프런트엔드 개발 도구는 [React 공식 가이드](https://react.dev/learn/creating-a-react-app)와 [Vite 공식 가이드](https://vite.dev/guide/)를 참고했습니다. 서버와 AI 공급자는 아직 선정하지 않았습니다.
