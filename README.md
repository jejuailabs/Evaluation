# 가치 돋보기 — SaaS 개발 프로젝트

사업을 계획하고, 함께 진행하고, 결과를 보고하는 일을 한곳에서. 일하면서 남긴 기록이 우리 조직의 성과가 됩니다.

**상태: 2026-10-05, 설계 v0.2 + 계정·조직·권한·서버 저장 1차 구현. 운영 출시 조건은 아직 모두 충족하지 않았습니다.**

## 웹페이지 열기

공개 체험 주소: [가치 돋보기 · 우리 조직의 작업실](https://value-lens-workspace.naggu1999.chatgpt.site/)

데모는 로그인 없이 기존 예시 데이터를 브라우저에서 체험합니다. 시작하기에서는 ChatGPT 계정으로 로그인한 뒤 새 조직을 만들거나 이메일 초대를 수락합니다. 실제 조직의 프로젝트와 파일은 D1·R2에 저장되며 API가 조직·프로젝트 권한을 확인합니다.

## 랜딩에서 들어오는 경로

- **데모 보기** → `?mode=demo#/home`: 기존 예시 조직과 프로젝트. 이전 로컬 체험 기록 유지.
- **시작하기** → `?mode=start#/start`: 실제 로그인 → 조직 목록/새 조직 → 예시 없는 작업실.
- **조직 관리** → 구성원 초대 링크·역할·프로젝트 배정·감사 기록.
- **전체 관리자** → 서버 허용 목록에 지정된 계정만 조직 상태·사용량·운영 이력을 관리.
- **이전 로컬 미리보기** → `?mode=preview#/start`: 기존 개인 미리보기 유지. 서버에 자동 업로드하지 않음.

## 이번 기초 구현

- 홈 / 프로젝트 / 자료함 / 보고서의 기본 탐색 구조, 네 가지 색상 테마, 반응형 화면.
- 예시 조직의 두 프로젝트, 프로젝트 추가, 업무 추가·상태 변경, 월별 업무 일정.
- 프로젝트에 파일 등록, 같은 문서의 새 버전 추가, 원본 내려받기. 파일은 이 브라우저의 IndexedDB에만 저장합니다.
- 프로젝트별 예산과 집행 기록, 예정/확정/지급 상태의 구분, 담당자별 조회.
- 목표·예상·확인된 실적의 분리, 증빙을 연결한 실적 입력과 확인, 누적 기준일별 이력.
- 프로젝트 시작일부터 선택 기준일까지의 보고서 스냅샷 생성, 재열람, 독립 HTML 내려받기.
- 도메인 타입, 계산·검증 함수, 상태 변경 함수, 저장 어댑터를 화면과 분리.

**이번 서버 단계:** 로그인, 복수 조직 소속, 조직 생성, 이메일에 묶인 초대 링크/수락/취소/만료, 구성원 권한·이용 중지, 프로젝트 참여 범위, 조직별 명령 API, 비공개 원본 저장·다운로드, 동시 변경 충돌·중복 요청 처리, 조직 및 전체 관리자 화면.

**아직 구현하지 않은 것:** AI 분석, OCR/HWPX 추출·편집·서식 재현, 실제 송금·정식 결재선, 백업/복구 인수 검증, 악성 파일 검사, 초대 메일 자동 발송, 실시간 동기화, 운영 규모 부하 검증. 전체 관리자 실사용 계정 지정과 실제 두 계정의 인수 확인은 별도 검증합니다. 상세 범위와 저장 한도는 06 문서가 기준입니다.

기존 `../value-lens`는 공개 랜딩페이지입니다. 이 폴더는 별도 SaaS 체험 사이트의 개발 코드이며 기존 랜딩페이지를 덮어쓰지 않습니다.

## 실행

Node.js 22.21 이상을 기준으로 확인합니다.

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 5174
```

주소는 `http://127.0.0.1:5174`입니다. 종료 후 다시 실행하면 같은 브라우저에 저장된 작업을 이어갑니다.

D1 초기 스키마는 `drizzle/`의 마이그레이션으로 관리합니다. 로컬·운영 DB는 별개이며, 로컬 적용은 Sites starter 절차를 따릅니다. 이 컴퓨터에는 필요한 패키지를 설치했습니다. Windows에서는 `start-dev.cmd`를 실행해도 개발 서버가 열립니다. 이 프로그램은 로컬 개발용이며 다른 컴퓨터에서 접속하는 공개 주소가 아닙니다.

```sh
npm test
npm run build
```

검증 결과와 미확인 범위는 [검증 기록](qa/verification.md)에 있습니다. 자동 검증 26개와 빌드는 통과했고, 브라우저 다운로드 수신·모바일 최종 캡처에는 도구 제약이 남아 있습니다.

## 코드 구조

```text
docs/                    제품 합의와 개발 기준
src/domain/              데이터 타입, 계산, 변경 규칙, 예시 데이터
src/infrastructure/      로컬 저장, 파일 저장, 보고서 출력
src/features/            홈·프로젝트·자료·예산·성과·보고서 화면
src/ui/                  공통 화면 요소와 색상 규칙
src/App.tsx              내비게이션과 화면 연결
tests/                   집계·예산·증빙·스냅샷 회귀 검증
```

## 다음 개발의 시작점

B1의 첫 구현을 마쳤으며, `docs/06-accounts-and-admin.md`의 남은 운영 출시 조건을 진행합니다. 서비스 연결 시 로컬 전체 상태 저장을 그대로 서버에 보내지 않습니다. 서버가 조직·권한·버전을 검증하는 명령 API와 트랜잭션으로 대체하고, 같은 도메인 검증을 재사용합니다. 저장 어댑터만 바꾸면 운영 서비스가 완성되는 구조라고 해석하면 안 됩니다.

이 시제품의 데이터 모델은 대화를 코드로 검증하는 최소 모델입니다. 전체 운영 모델과 권한·상태 전이 기준은 설계 문서가 기준입니다. 기능 변경 시 코드와 관련 문서의 상태를 같이 갱신합니다.

프런트엔드 개발 도구는 [React 공식 가이드](https://react.dev/learn/creating-a-react-app)와 [Vite 공식 가이드](https://vite.dev/guide/)를 참고했습니다. 서버·인증·파일 저장은 Sites의 인증/D1/R2를 사용합니다. AI 공급자는 아직 선정하지 않았습니다.
