# 가치 돋보기 — SaaS 개발 프로젝트

사업을 계획하고, 함께 진행하고, 결과를 보고하는 일을 한곳에서. 일하면서 남긴 기록이 우리 조직의 성과가 됩니다.

**상태: 2026-10-06, v0.6 · Vercel 배포 구조 유지. 기존 Supabase `projecthub`의 전용 `value_lens` 스키마·DB 계정·비공개 파일 저장소를 연결했고 실제 DB 연결 및 파일 업로드·다운로드·익명 접근 차단을 검증했습니다. 운영 주소는 `https://evaluation-five-xi.vercel.app`입니다. Production 환경변수 확인과 재배포로 로그인 요청의 403을 해소했고, 실제 운영 화면의 Google 버튼에서 Google 계정 로그인 화면까지 검증했습니다. 실제 계정 인증 후 복귀와 외부 사용자용 인증 메일 수신 검증은 남아 있습니다.**

**현재 종합 판정:** [전체 기능 점검](docs/13-current-implementation-audit.md), [가입·조직 참여](docs/14-email-otp-and-organization-keys.md), [현장 자료 AI 실적 검토](docs/15-field-outcome-analysis.md). 연간 계획→프로젝트 실행→현장 자료에서 AI 실적 제안→담당자 검토→관리자 확인→기간/연간 보고서를 연결했습니다. 사진·PDF·엑셀·HWPX 등에서 찾은 결과는 확인 전에는 집계하지 않으며, 최초 AI 제안·수정값·원본 근거를 보존합니다. 숫자 OTP·조직 가입키도 사용 가능합니다. 음성 처리, 실시간 협업, 저장 구조 확장, 기관별 보고 양식 등은 남아 있습니다. 전체 요구사항이나 운영 인수 완료 상태는 아닙니다.

**이메일 발송 설정 갱신:** Gmail SMTP 계정 인증과 Supabase 연결·설정 재조회를 완료했고, 프로젝트 발송 한도를 시간당 30건으로 설정했습니다. 이전 기본 발송 2건/시간·SMTP 미설정 기록은 과거 상태입니다. 숫자 인증번호 입력 화면과 검증 API를 추가했으며 기존 이메일 링크도 유지합니다. 사용자의 실제 메일 수신→최종 세션 발급 인수 검증은 별도입니다.

## Vercel 배포

[배포 설정·환경변수·DB 준비 순서](docs/12-vercel-deployment.md)를 먼저 확인하세요. Framework는 **Other**, Root Directory는 **./**, 빌드는 **npm run build:vercel**입니다. `vercel.json`에 설정을 포함했습니다. 로컬 DB 연결은 완료했으며 Vercel 환경변수는 별도 등록해야 합니다. `npm run check:services`로 DB·이메일/Google 제공자·비공개 버킷 설정을 확인합니다. 제공자 활성 여부는 실제 로그인 성공을 대신하지 않습니다.

## 이전 웹페이지 열기

이전 Sites 버전 공개 체험 주소: [가치 돋보기 · 우리 조직의 작업실](https://value-lens-workspace.naggu1999.chatgpt.site/)

데모는 로그인 없이 기존 예시 데이터를 브라우저에서 체험합니다. 현재 코드의 시작하기는 이메일 인증 링크 또는 Google/Supabase 인증으로 새 조직을 만들거나 이메일 초대를 수락합니다. 이메일·Google·DB 연결값과 실제 공급자 설정이 필요합니다. 실제 조직의 프로젝트와 파일은 Supabase PostgreSQL·Storage로 연결하며 API가 조직·프로젝트 권한을 확인합니다. 위 Sites 주소는 이전 배포이므로 현재 코드와 다를 수 있습니다.

## 메인과 작업실 경로

Vercel 도메인의 `/`는 기존 랜딩페이지를 표시합니다. `landing/index.html`과 `public/landing/`에 사진·그래픽·측정 기준·지표 체험을 함께 포함합니다. `/app`은 로그인과 조직 작업실이며, 예시 데이터는 데모를 선택했을 때만 열립니다.

- **데모 보기** → `/app?mode=demo#/home`: 기존 예시 조직과 프로젝트. 이전 로컬 체험 기록 유지.
- **시작하기** → `/app?mode=start#/start`: 실제 로그인 → 조직 목록/새 조직 → 예시 없는 작업실.
- **조직 관리** → 구성원 초대 링크·역할·프로젝트 배정·감사 기록.
- **전체 관리자** → 서버 허용 목록에 지정된 계정만 조직 상태·사용량·운영 이력을 관리.
- **이전 로컬 미리보기** → `/app?mode=preview#/start`: 기존 개인 미리보기 유지. 서버에 자동 업로드하지 않음.

## 기존 기초 구현

- 홈 / 프로젝트 / 자료함 / 보고서의 기본 탐색 구조, 네 가지 색상 테마, 반응형 화면.
- 예시 조직의 두 프로젝트, 프로젝트 추가, 업무 추가·상태 변경, 월별 업무 일정.
- 프로젝트에 파일 등록, 같은 문서의 새 버전 추가, 원본 내려받기. 데모는 브라우저 IndexedDB, 로그인한 조직은 비공개 Supabase Storage에 저장합니다.
- 프로젝트별 예산과 집행 기록, 예정/확정/지급 상태의 구분, 담당자별 조회.
- 목표·예상·확인된 실적의 분리, 증빙을 연결한 실적 입력과 확인, 누적 기준일별 이력.
- 프로젝트 시작일부터 선택 기준일까지의 보고서 스냅샷 생성, 재열람, 독립 HTML 내려받기.
- 도메인 타입, 계산·검증 함수, 상태 변경 함수, 저장 어댑터를 화면과 분리.

**이번 서버 단계:** 로그인, 복수 조직 소속, 조직 생성, 이메일에 묶인 초대 링크/수락/취소/만료, 구성원 권한·이용 중지, 프로젝트 참여 범위, 조직별 명령 API, 비공개 원본 저장·다운로드, 동시 변경 충돌·중복 요청 처리, 조직 및 전체 관리자 화면.

**문서·보고서 확장:** HWPX·DOCX·XLSX·PDF·텍스트의 본문 읽기, 원문 위치와 버전에 연결된 지표 설계, 여러 파일 등록, Word·Excel 보고서 출력을 연결했습니다. AI 초안 API와 로컬 실제 분석 호출을 검증했습니다. 운영 환경의 키·모델 설정 항목은 확인했으며 실제 Production AI 분석의 전체 화면 인수 검증은 별도입니다. 형식별 제한은 [10 문서](docs/10-documents-and-exports.md)가 기준입니다.

**예산·집행 확장:** 재원·세목 배정, 담당자 요청·보완·재요청, 관리자 1단계 승인, 부분 지급·입력 정정, 홈의 처리할 요청, 담당자별 집계와 기간별 지급 원장을 연결했습니다. 기존 집행 자료와 보고서를 유지합니다.

**현장 AI·협업 확장:** 사진·PDF·문서에서 실적 후보와 원본 근거를 제안하고, 담당자 검토→관리자 확인→보고서로 연결합니다. 프로젝트·업무·자료·실적·집행별 댓글, 구성원 확인 요청, 앱 내 알림, 작성 중 입력을 보호하는 25초 자동 갱신을 추가했습니다.

**아직 구현하지 않은 것:** 독립 OCR 도구·STT·TTS, 문서 원본 편집·서식 재현, 기관별 HWPX 출력, 실제 송금·다단계 결재선·정산 이월, 악성 파일 검사, 초대 메일 자동 발송, WebSocket 공동 편집, 반복 업무·미분류 자료함, 연간 예산의 프로젝트 배분 통제·도메인별 DB 분리. 전체 관리자 실사용 계정 지정, 백업/복구·부하·실제 두 계정 인수 확인도 남아 있습니다. 현재 종합 상태와 조직 JSON 1MiB 등의 운영 한도는 [13 문서](docs/13-current-implementation-audit.md)를 확인합니다.

기존 `../value-lens`의 랜딩을 이 저장소에 포함했습니다. Vercel에서는 소개와 작업실을 같은 도메인에서 제공합니다. 이전 Sites 배포는 별도로 유지됩니다. 예전 `/?mode=…` 링크는 쿼리·브라우저 해시를 유지하며 `/app`으로 연결합니다.

## 실행

Node.js 22.21 이상을 기준으로 확인합니다.

```sh
npm ci
npm run dev -- --host 127.0.0.1 --port 5174
```

주소는 `http://127.0.0.1:5174`입니다. 데모는 같은 브라우저에 저장된 작업을 이어가며, 로그인한 조직은 서버에서 불러옵니다.

신규 DB는 `.env.local` 연결값 설정 후 `npm run db:migrate`, 파일 저장은 `npm run storage:setup`으로 준비합니다. `drizzle/`는 이전 D1 스키마 기록이며 자동 데이터 이관은 하지 않습니다. 실행 안내는 [12 문서](docs/12-vercel-deployment.md)를 따릅니다.
