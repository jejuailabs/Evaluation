# 20. 보고서 검토·내부 승인·제출 기록

2026-10-06. 프로젝트 보고서와 연간 점검 보고서에 동일한 처리 절차를 연결했다. 보고 내용은 생성 시점의 스냅샷으로 유지하고 승인·제출 이력만 추가한다.

## 사용 흐름

1. 프로젝트 참여자는 **보고서 만들기**에서 기간과 결과 해석을 입력한다. 연간 보고서는 조직 관리자가 만든다.
2. 작성자 또는 관리자가 제출 예정 기관과 사유를 적고 **검토 요청**한다. 관리자는 홈의 **확인할 보고서**에서 해당 보고서를 연다. 프로젝트 검토 요청은 다른 관리자에게 앱 알림도 전달한다.
3. 관리자는 보고 내용을 대조한 뒤 **내부 승인**하거나 사유와 함께 **보완 요청**한다. 요청자가 검토 요청을 철회하면 초안으로 돌아간다.
4. 보완이 필요하면 원본 기록을 먼저 수정하고 **수정본 만들기**를 사용한다. 같은 기간의 최신 기록으로 새 초안을 만들며 해석을 다시 쓸 수 있다. 이전 보고서, 승인·제출 기록과 수정 사유를 보존하고 양쪽 화면에서 서로 이동할 수 있다. 하나의 보고서에서 수정본을 중복 생성할 수 없으며 후속 수정은 새 수정본에서 한다.
5. 승인한 보고서를 내려받아 실제 제출한 뒤 **제출 기록 남기기**에 제출일, 제출처, 경로, 파일 형식, 접수번호 또는 발송 확인 정보를 입력한다. 승인일 이전과 미래 날짜는 거절한다. 서로 다른 제출처·접수 기록은 추가할 수 있다.
6. 입력이 잘못된 제출은 사유와 함께 **무효화**한다. 원래 기록은 삭제하지 않는다. 유효한 제출 기록이 없어야 승인 철회가 가능하다. 무효화는 외부 제출을 회수하는 기능이 아니다.

## 권한·저장

- 참여한 프로젝트 안에서만 보고서를 만들고 읽는다. 일반 구성원은 본인이 만든 보고서만 요청·철회·수정본 생성할 수 있다. 승인·보완·승인 철회·제출 기록·무효화는 조직 관리자만 가능하다. 연간 보고서는 관리자 전용이다. 이전 보고서에 작성자 정보가 없으면 관리자가 처리한다.
- 서버가 처리자 ID·이름과 시각을 기록한다. 공개 명령은 보고서 종류·번호, 예상 처리 버전, 제한된 처리 입력만 받는다. 보고서 본문·승인 상태·처리 이력을 클라이언트에서 덮어쓸 수 없다.
- 보고서별 처리 버전과 조직 revision CAS를 함께 검사한다. 기존 operation 영수증과 command_token으로 중복 저장·알림 중복 및 경쟁 요청의 부분 반영을 막는다. 충돌하면 작성 중 폼을 유지하고 오류를 안내한다.
- 기존 `workspace_reports.data`, `workspace_annual_reports.data`에 작성자·이전 보고서 번호·처리 이력·제출 기록을 저장한다. 추가 DB 마이그레이션은 없다. 완료·보관 프로젝트도 보고 절차는 이어갈 수 있다.
- 보고서를 수정해 덮어쓰지 않는다. 새 수정본이 있어도 이전 승인·제출 상태와 본문을 보존한다. 이전 승인본의 제출 기록은 실제로 그 버전을 제출한 경우에 남긴다.

## 화면·출력

- 프로젝트와 연간 보고서 목록에 상태를 표시한다. 홈에는 검토 대기·보완할 보고서를 모으고 해당 보고서로 바로 연결한다. 연간 검토 요청은 홈에 표시하며 별도 앱 알림은 발송하지 않는다.
- 프로젝트 알림은 작성자·관리자에게 전달하며 현재 프로젝트 권한을 다시 확인한다. 권한이 회수되면 보고서와 관련 알림을 볼 수 없다.
- Word·Excel·HTML 및 인쇄/PDF에 보고서 번호, 현재 상태, 처리자·시각·사유, 제출/무효 기록, 이전 보고서 번호를 담는다. 처리 상태가 바뀌면 준비된 내려받기 링크를 폐기하고 새 파일을 만든다. 파일명에는 보고서 번호 일부와 처리 버전을 붙인다.
- 기관별 HWPX 서식, 다단계 결재선, 전자서명, 외부 기관 자동 전송·접수 조회는 포함하지 않는다. 제출 기록은 담당자의 입력이다. 실제 제출 파일의 업로드·해시 검증은 하지 않으며, 내보내기에는 생성 시점의 최신 처리 이력이 반영된다.

## 검증

- 전체 자동 검사 **138/138**, TypeScript 검사 통과. 보고 상태 전이, 원본 보존, 수정본 연결, 잘못된 날짜·오래된 버전 거절, 역할·프로젝트 격리, 연간 보고서, Word·Excel·HTML 출력과 주입 방어를 확인했다.
- 실제 PostgreSQL 문법·스키마를 적용한 PGlite 합성 조직에서 저장/재조회, 서버 작성자 기록, 알림, 중복 재시도, 경쟁 승인 중 한 건만 저장, 프로젝트 권한 회수를 검증했다. 실제 기관에 보고서를 보내지 않았다.
- 실제 React 화면과 서버 API에서 담당자 요청→관리자 보완→담당자 수정본→관리자 승인→제출 기록→재조회→무효화까지 확인했다. 연간 보고서의 상태 갱신과 직접 링크, 처리 중 오래된 폼의 덮어쓰기 차단, 승인 후 이전 다운로드 링크 폐기도 확인했다. 390px 모바일에서 가로 넘침 0, 브라우저 오류 0이며 데스크톱·모바일 화면을 직접 확인했다.
