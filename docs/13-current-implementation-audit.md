## 제품의 핵심 흐름

현재 가능한 흐름은 다음과 같다.

1. 로그인 후 조직을 만들고 연간 계획·목표를 등록한다.
2. 프로젝트·담당자·업무·일정·예산을 정하고 프로젝트 지표를 연간 목표에 연결한다.
3. 사업계획서를 읽고 AI의 지표 초안을 검토하거나 지표를 직접 설계한다.
4. 진행 중 문서·현장 기록·집행 내역을 모으고, 담당자가 실적과 근거 파일 버전을 연결해 입력한다.
5. 관리자가 확인한 실적만 대시보드와 기간 보고서에 반영한다.
6. 프로젝트 또는 연간 보고 시점의 내용을 고정하고 Word·Excel·HTML로 받는다.

**아직 연결되지 않은 핵심은 ‘사진·녹음·엑셀 등 현장 자료 → AI의 실적 수치 제안 → 검토·확정’이다.** 현재 AI는 계획 문서의 지표 설계를 보조한다. 실행 실적 입력과 결과 해석은 사람이 수행한다. 따라서 계획부터 사후 보고까지 AI가 자동 처리한다고 설명하면 안 된다.

## 운영 규모와 데이터 구조

- 조직의 업무 상태를 `organizations.body`의 JSON 한 덩어리로 보관한다. 소속·원본 파일·초대·감사 등의 별도 테이블은 있으나 프로젝트·업무·실적은 각각 독립된 행 구조가 아니다.
- 현재 JSON 저장 한도는 **조직당 1MiB**다. 연간 업무와 변경 이력이 늘어날 때 한도와 동시 변경 충돌이 병목이 될 수 있다. ‘1년 운영 전체를 수용한다’는 인수를 위해 도메인별 저장·조회 분리, 페이지 단위 조회와 실제 규모 테스트가 필요하다.
- 원본 파일은 건당 **25MiB**, 조직당 **500MiB**, 일괄 등록은 최대 12개다. 허용 확장자를 제한하지 않는 것과 모든 형식의 분석을 지원하는 것은 다르다.
- 문서 추출량·처리시간, AI 입력량·45초 제한·조직당 하루 20회 제한이 있다. 장시간 백그라운드 처리·재개 큐는 없다.
- 업로드 잔여 파일 정리 명령은 있지만 자동 실행 일정은 등록하지 않았다. 악성 파일 검사와 복구 훈련도 남았다.
- 보고서는 생성 순간의 데이터 상태를 기간 조건으로 집계한다. 과거 날짜의 승인 상태까지 재현하는 회계 원장이나 공식 외부 평가 결과가 아니다.
- 공유 Supabase 프로젝트 안에 전용 스키마·DB 권한·파일 저장소를 둔다. Auth와 발송 한도 등은 프로젝트 단위로 공유한다.

## 남은 개발 우선순위

1. **가입과 공동 운영 완결:** 숫자 OTP 입력/검증, 조직 가입키, 관리자 계정 지정, 실제 두 계정의 가입→조직 참여→권한별 저장/조회 인수. 확인된 모바일 보고서 넘침 수정.
2. **제품 핵심 AI 연결:** 현장 사진·엑셀·보고서·음성을 읽어 실적 후보와 출처를 제안하고, 담당자 검토/관리자 확정 이후 집계. 자동 제안을 확인된 성과로 바로 계산하지 않는다.
3. **1년 운영을 감당하는 구조:** 조직 JSON 1MiB 한도 해소를 위한 저장 구조 분리, 증빙/버전 이관, 목록 조회·동시 변경·파일 용량 정책, 백업 복구·부하 검증. 연간 예산과 프로젝트 배분도 연결.
4. **일상 협업 보완:** 댓글·멘션·알림·반복 업무·실시간 반영·미분류 자료 수집. 평가 기능과 함께 일상 운영이 충분히 편리한지 실제 조직으로 확인.
5. **제출 가능한 보고:** 기관 양식 매핑·HWPX 등 출력, 사진·근거 자동 편집, AI 서술 초안, 보고서 승인과 제출 이력.

완성도를 단일 백분율로 표시하지 않는다. 구현된 업무 흐름, 누락된 요구사항, 실제 운영 인수 결과가 서로 다른 상태이기 때문이다.
