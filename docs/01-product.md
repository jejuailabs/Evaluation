# 01. 제품과 범위

상태: 설계 기준 v0.1 · 2026-10-05. 이 문서의 ‘필수’는 출시 조건이며 구현 완료 표시가 아닙니다. 현재 구현 상태는 README와 05를 참고합니다.

## 제품 정의

사회적기업·사회적협동조합 등 조직이 프로젝트를 운영하면서, 시작할 때 평가를 설계하고 진행 중 근거를 쌓아 종료 시 쉽게 보고하는 조직 운영 SaaS.

프로젝트 운영의 완성도가 제품의 기반이다. 평가 설정을 끝내야 업무를 등록할 수 있는 구조를 만들지 않는다. 반대로 평가를 종료 시 한 번 실행하는 별도 도구로 만들지도 않는다.

> 사업을 계획하고, 함께 진행하고, 결과를 보고하는 일을 한곳에서. 일하면서 남긴 기록이 우리 조직의 성과가 됩니다.

## 사용자와 해결할 일

| 사용자 | 자주 하는 일 | 필요한 결과 |
| --- | --- | --- |
| 현장 담당자 | 일정 확인, 활동·사진·참여 기록, 지출 증빙 등록 | 짧은 입력으로 업무와 증빙이 함께 정리됨 |
| 프로젝트 책임자 | 업무 배분, 일정 변경, 예산·성과 점검 | 늦는 업무와 미확인 기록을 한곳에서 처리 |
| 조직 관리자 | 프로젝트·인력·재원 배분, 승인, 종합 보고 | 프로젝트와 담당자별 운영 상태 및 근거 조회 |
| 회계 담당자 | 집행 검토, 지급, 배분, 정산 | 예산·확정 비용·약정·지급·증빙의 구분 |
| 평가·보고 담당자 | 지표 정의, 조사, 실적 검토, 제출 | 수치와 출처가 연결되고 제출 버전이 보존됨 |
| 외부 협력자 | 요청받은 자료 제출, 제한적 검토 | 필요한 프로젝트·자료에만 접근 |

실제 조직마다 한 사람이 여러 역할을 맡는다. 역할 이름을 화면 메뉴로 강요하지 않는다.

## 핵심 연결

사업계획 → 활동과 목표 → 업무·일정·예산 → 현장 기록·증빙 → 확인된 실적 → 기간 집계·차트·보고서.

- 목표: 달성하기로 합의한 수치·상태. 변경 시 승인된 새 버전과 이유를 남긴다.
- 예상: 자원·기간·활동량 등의 가정으로 추정한 결과. 계산 근거와 불확실성을 보관한다.
- 실적: 해당 정의·기간·범위에서 확인된 결과. 원문·계산·검토자를 추적한다.
- 업무 완료, 활동량, 사람에게 발생한 변화는 서로 다른 값이다.
- 정성적 변화는 사례·설문·인터뷰·관찰기준으로 설명할 수 있어야 한다. 무조건 점수로 환산하지 않는다.

## 첫 운영 출시에서 갖춰야 할 범위

1. 조직·팀·멤버·프로젝트 권한, 초대/탈퇴/인수인계.
2. 프로젝트·담당자·업무·일정·상태, 기본 목록/보드/캘린더, 반복업무와 알림.
3. 자료함, 원본 파일과 버전, 자유 기록, 프로젝트 간 참조, 검색.
4. 프로젝트·담당자·재원별 예산, 집행 신청·승인·확정·지급·증빙.
5. 계획에서 지표를 설계하는 AI 보조, 목표/예상/실적, 정량·정성 기록, 증빙 검토.
6. 기간과 범위가 명확한 대시보드 및 검증된 출력 양식의 보고서.
7. 권한·감사기록·백업·복구·실패 처리·접근성. AI가 지연되어도 기본 업무는 가능.

## 이후 확장할 기능

- 회의 녹음/STT → 회의록·결정·업무 연결, TTS, 변환/OCR, 번역·문서 비교.
- 대외 자료 요청·설문·모바일 현장 수집, 오프라인 작성과 중복 방지 동기화.
- 복수 재원, 공통 인건비·간접비 배분, 수익·입금 예정, 조직 포트폴리오와 인력 가용량.
- 지표 버전 라이브러리, 참여자 중복 제거, 코호트 추적, 전후·장기 변화.
- 일정·메일·회계·드라이브 연동, 반복 사업 복제, 제출 의무/마감 관리.

## 범위와 약속

- ‘모든 파일’은 입력을 최대한 폭넓게 받겠다는 방향이다. 저장/추출/편집/출력 수준을 형식별로 알린다.
- IRIS+는 정의를 참조하여 적용 여부를 판단한다. SDGs는 목표 연결이며 인증 표시가 아니다. SVI/SPC 점수·공식 평가를 자동 보증하지 않는다.
- AI는 원문과 제안 이유를 함께 보여 준다. 근거 없는 목표·성과를 사실처럼 채우지 않는다.
- 최초 고객과 함께 대표 문서·보고 양식을 정해야 출시 범위를 확정할 수 있다. 현재 가상 샘플은 고객 수요나 효과의 검증 자료가 아니다.

## 성공을 판단할 지표

실제 파일럿에서 기록 등록까지의 단계·소요 시간, 같은 정보의 재입력 횟수, 증빙 누락, 보고서 생성 후 수정량, 수치의 원문 추적 성공률, 업무 누락과 오류를 관찰한다. 수치 목표는 파일럿 기준선을 확보한 뒤 합의한다. 임의의 ‘시간 80% 절감’ 같은 성과를 선언하지 않는다.

## 유지할 디자인 원칙

큰 글자, 분명한 위계, 차분한 색과 여백. 네 가지 테마를 유지하되 의미를 색만으로 전달하지 않는다. 장식용 차트·과장된 AI 표현보다 당장 해야 할 일과 다음 행동을 먼저 보여 준다. 생성 이미지는 소개 화면에 활용하고 운영 화면에서는 현장 자료·실제 지표·읽기 쉬운 차트를 우선한다.
