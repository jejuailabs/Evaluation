# 09. 연간 계획부터 현장 운영·평가·보고까지

2026-10-06. 기존 SaaS의 계정·조직·권한·프로젝트·자료·집행·실적 명령을 이어서 확장했다. 새 프로젝트로 다시 만들거나 기존 자료를 초기화하지 않는다.

이 문서는 v0.3 연간 운영 확장의 기록이다. 이후 문서 추출·설계 근거·파일 출력의 구현 상태는 [10. 문서와 보고서 출력](10-documents-and-exports.md)을 함께 확인한다.

## 제품의 중심

조직이 일 년의 목표를 정한다. 프로젝트마다 담당자·기간·예산·업무와 확인할 변화를 정한다. 현장에서 남긴 기록과 원본을 실적에 연결하고 담당자가 확인한다. 연간 화면은 연결된 프로젝트 결과를 모으고, 분기·연말 점검본은 그때의 숫자와 해석을 보관한다. 평가는 일상 업무와 같은 자료를 사용한다.

## 집계 계약

- **누적/시점**: 종료일 이전의 최신 확인값. 월별 누적값을 더하지 않는다. 분기 보고에서도 분기 증가분이 아닌 최신 상태로 명시한다.
- **기간별 합계**: 시작·종료일이 있는 겹치지 않는 기록만 합산한다. 선택 범위 경계에 걸친 기록은 임의로 나눠 계산하지 않고 경고한다.
- **비율**: 확인된 기간의 분자 합계 / 분모 합계 × 100. 비율끼리 단순 평균하지 않는다. 분모는 양수, 분자는 분모 이하이다.
- **정성**: 관찰·인터뷰 등 근거와 함께 변화 없음/일부 변화/기준 충족을 기록한다. 자동 숫자 점수나 달성률로 바꾸지 않는다.
- **감소 목표**: 실제가 목표 이하이면 충족 100%, 초과이면 목표/실제 비율. 이는 절감률이 아니다.
- **연간 합산**: 단위·방향이 같은 수량만 가능. 합산·중복 제외 근거를 입력해야 한다. 중복 가능 이용자는 실제 고유 식별자 중복 제거가 구현되기 전까지 개별 보기로 운영해야 한다. 연결 지표의 확인값이 없거나 기간 경계가 불분명하면 전체 합계를 만들지 않는다.
- **여러 해의 누적값**: 전년도부터 쌓인 누적 지표는 해당 연도의 실적으로 자동 합산하지 않는다. 연도별 지표 또는 명시적 기간 기록이 필요하다.
- **정정**: 원본과 같은 집계 기간에 새 기록을 남기고 확인하면 원본을 대체한다. 원본은 삭제하지 않는다. 먼저 확정된 정정본이 있으면 다른 정정은 다시 검토해야 한다.
- **보고**: 생성 시점에 확인된 자료를 사용하는 고정본이다. 이후 과거 날짜의 비용·실적이 수정돼도 기존 보고서는 바뀌지 않는다. 업무/비용의 과거 상태를 이벤트로 재현하는 기능은 아직 아니다.

## 저장과 호환성

기존 `Workspace`에 `annualPlans`, `annualGoals`, `annualReports`, `activities`를 추가했다. 이전 저장 데이터에서 필드가 없어도 빈 배열로 확장한다. `schemaVersion: 1`과 기존 브라우저 저장 키를 유지한다. 새 조직은 빈 상태로 시작하고, 새 데모에만 연결된 연간 목표 예시가 있다. 이전 데모의 사용자 변경을 덮어쓰지 않으므로 기존 방문자는 첫 연간 계획을 직접 만들 수 있다.

서버는 동일 명령 API의 엄격한 스키마·조직 권한·revision 충돌·재시도 검증을 사용한다. 현장 기록의 작성자는 서버가 로그인한 구성원으로 지정한다. 파일 원본은 기존 R2 정책을 유지한다. 이번에 Supabase DB 이전을 하지 않았다.

## 여전히 남은 필수 개발·외부 연결

1. **Google 로그인 실제 활성화**: 08 문서의 Supabase 연결 대상·Google OAuth 설정 필요. 공개 서비스는 기존 ChatGPT 인증이며, Google 운영 인수를 완료했다고 볼 수 없다.
2. **문서 분석 AI**: 모델 서비스 연결, HWPX/PDF/DOCX/엑셀 추출, 원문 위치를 가진 제안, 사람의 확정, 비동기 작업·실패 재시도. 현재 기준 라이브러리와 가정 계산기는 수동 지원 기능이다. AI 분석으로 표시하지 않는다. OpenAI Developers 연결이 제안되었고, 아직 연결·키 설정을 확인하지 못했다.
3. **자료 운영**: 한 번에 여러 파일 직접 업로드, 미분류함, OCR·미리보기, 원문 검색, 문서 차이 비교·복원, 녹음/STT·TTS·변환, 파일 검사·정리.
4. **협업·예산**: 댓글·알림·실시간 동기화, 하위/반복/의존 업무, 재원·세목 배분, 결재선·반려·수정/취소·부분 지급·정산. 현재 지급 상태는 장부 기록이며 실제 송금이 아니다.
5. **보고 서식**: 실제 기관 양식의 HWPX/DOCX/PDF 출력, 사진 배치·증빙 묶음, 검토·제출·정정 승인. 현재 독립 HTML 출력이다.
6. **운영 규모**: 현재 조직 작업 데이터 JSON 1MiB·원본 500MiB·파일 25MiB 한도. 1년치 대량 운영 출시 전 정규화 저장·페이지 단위 로딩·첨부/스냅샷 분리·백업/복구·부하 검증 필요. 한 화면의 연간 흐름이 구현됐다는 이유로 운영 규모 검증을 완료 처리하지 않는다.

> 문서 입력·AI 초안 연결·보고서 출력은 이후 v0.4에서 확장했습니다. 현재 상태는 [10번 문서](10-documents-and-exports.md)를 우선 확인하세요. 아래 검증은 v0.3 시점입니다.

## 검증

45개 자동 테스트: 기존 인증·권한·저장 + 기간 집계/가중 비율/정성/감소 목표/정정/변경 이력/현장 증빙/연간 보고/프로젝트 마감/기존 데이터 호환. 서버 통합 테스트로 연간 계획 → 프로젝트 지표 → 일반 구성원 현장 기록 → 관리자 실적 확인 → 연간 보고 저장, 일반 구성원의 조직 전체 보고 접근 차단을 확인했다.

브라우저에서 기존 데모 보존, 연간 계획·목표 연결 저장, 9월 말 86명과 현재 91명 구별, 기간 보고 저장, 현장 기록과 자료·지표 연결, 통합 업무 보드, 모바일 가로 넘침 없음을 확인했다. 타입 검사와 배포 빌드가 통과했다. Google 두 계정 운영 인수·AI·파일 변환은 검증 대상이 아니다.
