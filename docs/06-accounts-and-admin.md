# 06. 계정·조직·관리자 — 합의와 구현 기록

2026-10-05. 사용자의 “조직별 개별 로그인과 구성원 연결, 조직 관리자, 서비스 전체 관리자” 요구를 다음 단계의 기준으로 고정한다.

추가 결정: 사용자가 Google 로그인을 요구했다. 현행 공개 인증과 별도로 Supabase Auth 연결 코드를 준비했으며 실제 전환 상태는 [08](08-google-and-supabase.md), 전체 기능 재점검은 [07](07-implementation-audit.md)에 기록한다.

## 합의한 구조

- 개인 계정은 전역 사용자다. 한 계정은 여러 조직에 소속될 수 있다.
- 새 조직 생성자는 조직 대표이며, 최초 작업실에는 예시 데이터가 없다.
- 초대받은 사람은 자기 계정으로 로그인하고 초대를 수락한다. 이메일 일치 없이 조직에 자동 가입시키지 않는다.
- 조직원은 참여 프로젝트에서 업무·자료·예정 집행·성과를 기록한다. 읽기 전용 역할은 조회만 한다.
- 조직 대표와 관리자는 구성원 및 프로젝트 참여를 관리한다. 관리자 승격과 변경은 대표에게 제한한다.
- 전체 관리자는 별도 화면에서 조직 상태와 사용량을 관리한다. 조직 내부 문서·예산의 자동 열람 권한을 부여하지 않는다.
- 일상 화면은 홈·프로젝트·자료함·보고서를 유지하고, 조직 관리 메뉴만 권한에 따라 추가한다.

## 이번 구현

Sites의 서버 인증과 D1·R2를 사용한다. 랜딩과 데모의 공개 접근은 유지한다. 로그인 제공자는 현재 ChatGPT다. 조직과 프로젝트 권한은 인증 제공자가 아닌 애플리케이션 API가 매 요청 검증한다.

| 경로 | 동작 |
| --- | --- |
| `?mode=demo#/home` 또는 기존 기본 주소 | 이전 브라우저 예시 데모, 서버 조직 데이터와 분리 |
| `?mode=start#/start` / `?mode=app` | 로그인 → 소속 조직 목록·새 조직 생성 |
| `?mode=app&org=…#/home` | 선택 조직의 서버 저장 작업실 |
| `#/admin` | 조직 대표·관리자의 구성원·초대·프로젝트 배정·감사 기록 |
| `?mode=app#/platform` | 서버 허용 목록의 전체 관리자 전용 |
| `?mode=preview#/start` | 이전 브라우저 개인 미리보기 데이터 유지, 자동 서버 이전 없음 |

계정·조직·멤버십·프로젝트 참여·초대·파일 메타데이터·명령 감사·전체 관리자 감사는 별도 관계형 테이블이다. 기존 프로젝트 도메인은 서버에서 검증하는 명령 API 뒤로 옮겼다. 초기 단계에서는 조직의 프로젝트 상태를 서버의 버전 있는 JSON 문서로 보관한다. 브라우저 전체 상태를 그대로 업로드하는 API는 없다. 조직 상태의 최대 JSON 크기는 UTF-8 기준 1MiB이며 확장 시 프로젝트·업무 등의 행 단위 저장으로 마이그레이션한다.

## 권한과 저장 규칙

- 모든 데이터 API는 로그인 사용자·활성 멤버십·조직 상태를 확인한다. 일반 구성원에게는 배정된 프로젝트의 데이터만 응답한다.
- 명령은 명시적인 스키마로 검증한다. 조직원은 프로젝트 생성·지표 설계·실적 확정·집행 상태 확정·보고서 생성을 할 수 없다. 현재 이 동작은 조직 관리자 역할에 한정한다.
- 변경은 예상 revision과 요청 UUID를 사용한다. 서버의 CAS 갱신과 감사 기록을 D1 batch로 묶는다. 초대·역할·프로젝트 배정 변경도 같은 조직 revision을 증가시켜 오래된 권한을 사용한 쓰기를 차단한다.
- 초대 토큰은 7일 유효한 256비트 임의 값이다. 원문 토큰은 생성 응답에만 반환하며 DB에는 SHA-256 해시를 보관한다. 토큰뿐 아니라 인증 이메일을 검사한다. 취소·만료·재사용은 거부한다. 이메일은 자동 발송하지 않고 관리자가 링크를 전달한다.
- 조직 대표의 제거·강등과 일반 관리자의 관리자 승격은 금지한다. 대표 이전과 별도 결재 역할은 후속 기능이다.
- 원본은 비공개 R2에 보관하고 다운로드 API가 조직·프로젝트 접근권을 검사한다. 원본을 HTML로 인라인 실행하지 않고 attachment로 내려준다. 파일당 25MB, 조직당 기본 한도 500MB다.
- 서버 파일 등록은 업로드 완료 메타데이터를 검증·정규화한다. AI 분석·바이러스 검사·HWPX 내용 추출은 아직 연결하지 않았다. 현재 원본은 다운로드용으로만 제공한다.
- API 응답은 no-store이고 변경 요청은 same-origin 및 전용 요청 헤더를 확인한다.

## 전체 관리자 초기 지정

호스팅 서버 환경 변수 `PLATFORM_ADMIN_USER_IDS`에 인증된 Site 사용자 ID를 쉼표로 지정한다. 클라이언트에 이 값을 전달하지 않는다. 빈 값이면 모든 사용자에게 전체 관리자 권한을 거부한다. 첫 방문자를 전체 관리자로 만드는 자동 부트스트랩은 금지한다.

전체 관리자는 조직별 구성원 수·파일 수·사용량·상태를 조회하고 사유를 남겨 일시 정지·해제할 수 있다. 내부 프로젝트·문서·예산을 조회하는 지원자 위임 기능은 구현하지 않았다. 전체 관리자 지정 계정은 실제 로그인으로 확인한 후 설정한다.

## 남아 있는 운영 출시 조건

백업·복구 연습, 악성 파일 검사·격리, 업로드 중단 시 미참조 객체 정리, 업로드 총량의 동시 요청 정밀 제한, 조직 대표 이전, 결재선·자기 승인 정책, 알림·메일 발송, 실시간 갱신, 세부 문서 접근권, 부하/대용량 모델 분리, 실제 두 계정의 운영 환경 인수 테스트가 남아 있다. 이 구현을 B1 전체 운영 출시 완료로 표시하지 않는다.

인증 연동 오류가 발생해도 기존 공개 데모를 없애지 않는다. 개발 환경의 Seedy 인증 시뮬레이션은 공식 starter의 loopback 개발 모드에 한정하며 배포 결과물에는 포함하지 않는다.
