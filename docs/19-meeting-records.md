# 19. 회의 녹음·음성 전사·검토한 회의 기록

2026-10-06. 18 문서의 녹음 원본 보관을 전사·검토·프로젝트 활동 연결까지 확장했다. 전체 제품이나 운영 인수가 완료된 상태는 아니다.

**배포 상태:** 로컬 구현·검증 완료. main 푸시 후 기존 Vercel 자동 배포가 실행된다. 운영 배포 성공 여부는 별도 확인이 필요하다.

## 사용 흐름

1. **자료함 → 미분류 자료함 → 회의 녹음**에서 참석자에게 녹음을 알리고 동의를 확인한 뒤 브라우저 마이크로 녹음한다. 녹음 마치기 후 재생·내려받기·원본 보관이 가능하다. 브라우저 녹음은 한 번에 10분이며 화면을 열어 둔다. 마이크 거부나 지원하지 않는 브라우저에서는 기존 파일 모으기로 휴대폰 녹음 등을 올린다.
2. 음성 항목의 **전사·회의 기록**에서 원본을 듣고 **AI로 음성 전사**를 실행한다. 선택한 녹음 전체를 OpenAI로 전송한다. 한국어 전사를 기본으로 하며 화자 구분·번역·자동 회의 요약은 하지 않는다. 직접 전사문을 작성하는 방법도 제공한다. 공개 데모는 녹음 보관·수동 기록만 가능하다.
3. 전사문과 **회의 내용·결정·할 일**을 수정하고 초안으로 저장한다. AI 최초 전사문은 별도로 보존하고 화면에서 대조할 수 있다. 원본 확인 체크 후 **검토한 회의 기록 확인**으로 확인자와 시각을 기록한다. 확인 뒤 다시 초안으로 수정하면 재확인이 필요하다.
4. 자료함의 **프로젝트 연결**에서 활동일·기존 업무·목표를 선택한다. 음성 원본의 ID를 유지하고, 확인한 전사문과 회의 내용은 별도 텍스트 문서로 만든다. 활동에는 음성과 회의 기록 두 근거를 함께 연결한다. 연결한 원본은 프로젝트 자료의 내용 열기에서 재생·회의 기록 열람이 가능하다.

검토하지 않은 회의 초안은 프로젝트에 연결할 수 없다. 회의 기록이 없는 일반 음성 파일은 이전과 같이 원본만 분류할 수 있다. 확인은 회의 내용의 검토이며 실적 확정이 아니다. 활동은 보고서에 포함되지만 성과 수치는 기존 실적 제안·담당자 검토·관리자 확인 절차를 따라야 한다. 새 후속 업무의 자동 생성은 포함하지 않으며 기존 업무에 연결한다.

## 범위와 한도

- 전사는 파일당 **25,000,000바이트**, 전사문 **30,000자**, 회의 내용 **10,000자**까지다. 원본 자료함의 기존 25MiB·조직 500MiB 한도와 구분한다. MP3·MP4/M4A·MPEG/MPGA·WAV·WEBM·OGG·FLAC의 확장자와 파일 서명을 검사한다. 컨테이너에 실제 음성이 없거나 코덱을 읽지 못하면 제공자 오류를 안내한다.
- 조직당 24시간 **20회**. 서버에서 시작한 실패 요청도 한도에 포함한다. 중복 클릭과 2분 이내 진행 중 재요청은 거절한다. 이미 저장된 초안의 재요청은 초안을 돌려주고 다시 과금 요청을 보내지 않는다.
- 원본 읽기 제한 10초, 전사 제공자 호출 제한 45초. 서버 함수 최대 실행 시간을 120초로 확장했다. 전사 응답이 실패하면 실패 상태와 안내 문구를 보존하고 같은 원본에서 재시도할 수 있다. 실행 프로세스가 종료돼 진행 상태만 남으면 2분 후 재시도한다. 원본은 삭제하지 않는다.
- AI 완료 시 확인 전 초안을 서버에 저장한다. 화면 응답을 잃어도 새로고침으로 복구한다. 전체 브라우저 녹음 자동 복구, 긴 녹음 분할, 백그라운드 작업 큐·자동 재시도·화자별 타임라인·TTS는 후속 과제다. 브라우저를 닫기 전에는 녹음 파일을 보관하거나 내려받아야 한다.
- 모델은 `gpt-4o-mini-transcribe`, 기존 `OPENAI_API_KEY`를 사용한다. 별도 키·DB 마이그레이션·Supabase 설정 변경은 필요하지 않다. API 계약은 [OpenAI 전사 API](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create), 파일 한도는 [음성 전사 안내](https://developers.openai.com/api/docs/guides/speech-to-text)를 확인했다.

## 권한과 저장

- 미분류 원본·전사문·검토 내용은 올린 구성원과 조직 관리자만 접근한다. 읽기 전용 구성원은 전사·수정할 수 없다. 연결한 이후에는 기존 프로젝트 참여 권한으로 조회하며 회의 기록은 변경하지 않는다. 보관한 미분류 항목은 복원 후 수정한다.
- `workspace_intake_items.data`에 전사 시도 상태·식별자·시각, AI 원문·모델, 수정 전사문·회의 내용·검토 버전을 저장한다. 원본·검토 기록·확인자와 시작/실패/완료/초안 저장/확인 이력을 유지한다. 매번 편집한 모든 중간 문장의 스냅샷을 보관하는 기능은 아니다.
- 전사 시작·완료도 **조직 revision CAS + operation 영수증 + 새 command_token**을 사용한다. 실패한 저장이나 오래된 전사 완료는 최신 시도의 결과를 덮어쓰지 못한다. 외부 파일 읽기 뒤와 결과 저장 때 구성원 권한을 다시 확인한다.
- 전사 시작/완료 명령은 내부 전용이며 공개 명령 스키마에서 받지 않는다. 클라이언트가 AI 원문·모델·확인자·확인 시각을 위조할 수 없다. 회의 편집은 별도 기록 버전까지 검사하므로 충돌 후 무심코 다른 사람의 회의 내용을 덮어쓰지 않는다.
- 프로젝트 분류는 기존 트랜잭션 안에서 원본 귀속 변경·음성 문서·회의 텍스트 문서·활동·분류 이력을 함께 저장한다. 중간 검증 실패 시 모두 취소한다. 원본을 Storage에서 복사하지 않는다.

## 검증 기록

- 전체 자동 검사 **132/132**, TypeScript 검사 통과. 전사 요청 multipart 계약·실패/빈 응답/길이 제한, 원문 보존, 확인 전 연결 차단, 오래된 전사와 편집 충돌, 재시도, 동시 요청 한도, 권한 격리·회수, 프로젝트 권한 이전을 포함한다.
- 실제 React 화면 + 서버 API + PGlite 합성 조직에서 가짜 브라우저 마이크 녹음→원본 보관→전사 실패/재시도→초안 수정→검토 확인→기존 업무·활동·두 근거 연결→재조회까지 확인했다. 마이크 트랙 해제, 녹음 중 Escape로 잘못 닫히지 않음도 검사했다. 390px 모바일 가로 넘침 0, 화면 오류 0. 모바일 자료 행의 버튼 넘침을 수정했다.
- Windows 내장 음성으로 만든 합성 한국어 WAV를 실제 OpenAI API에 전송해 56자 전사문을 확인했다(약 2.6초). 실제 고객 음성·로그인 프로필·외부 사용자 메시지를 사용하지 않았다.
- 실제 Supabase 서버 역할에서 합성 회의 자료 1건·문서 3건·활동 1건을 저장/재조립하고 AI 원문 보존을 확인했다. 트랜잭션 전체를 롤백했으며 잔여 검증 조직은 0건이다.

나머지 제품 개발은 기관별 보고 양식/HWPX·외부 자동 제출, 다단계 결재·정산 이월, 긴 AI 작업 큐, 독립 항목 충돌 병합·화면별 조회, 실제 두 계정 인수·전체 관리자 지정·백업 복구 훈련 등이다.

보고서 내부 승인·보완·수정본·제출 기록은 후속 [20 문서](20-report-approval-and-submission.md)에서 구현했다.
