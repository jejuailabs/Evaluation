# 16. 프로젝트 대화·알림·자동 변경 반영

2026-10-06. 연간 계획 → 업무 수행 → 현장 기록 → 실적 검토 → 보고의 기존 흐름에 협업 기능을 추가했다.

## 사용할 수 있는 기능

- 프로젝트의 **대화** 탭에서 프로젝트 전체 또는 특정 업무·현장 기록·자료·실적·집행을 선택해 의견을 남긴다. 각 항목 옆 **댓글** 링크로 같은 대화에 진입한다.
- 확인을 부탁할 구성원을 최대 10명 선택한다. 새 댓글은 선택한 사람, 프로젝트 담당자, 그 대화에 댓글을 남겼던 사람에게 앱 내 알림을 만든다. 본인에게는 알리지 않는다.
- 작성자는 댓글을 수정하고 이력을 볼 수 있다. 작성자 또는 조직 관리자는 삭제할 수 있다. 삭제 시 본문과 수정 이력은 지우고 삭제 상태·시각·처리자만 남긴다.
- 업무 배정/담당자·마감일 변경은 담당자에게, 완료는 프로젝트 담당자에게 알린다. 실적 등록·집행 요청은 관리자에게, 실적 확인/보완·집행 승인/보완/지급/취소는 해당 담당자에게 알린다.
- 상단 **알림**에서 미확인 개수를 보고, 알림을 누르면 해당 항목의 대화와 원래 화면으로 이어진다. 읽음 처리와 이전 알림 보기를 지원한다.
- 조직의 새 버전과 알림 개수를 **25초마다** 확인한다. 업무 데이터가 바뀌었을 때만 작업실 내용을 다시 받는다. 다른 탭에서 돌아오거나 연결이 복구될 때도 확인한다.
- 양식·댓글 작성 중이거나 저장 중이면 자동 적용을 보류한다. 늦게 도착한 응답으로 최신 저장 내용을 되돌리지 않는다. 권한이 회수되면 현재 세션의 접근을 다시 확인한다.

앱 내부 알림이며 이메일·휴대전화 푸시 발송은 아니다. WebSocket 공동 편집이나 접속자 표시 기능은 아니다. 데모에는 대화 진입 경로와 로그인 안내를 제공하고, 실제 공유 댓글은 로그인한 조직에서 사용한다.

## 저장과 권한

- `value_lens.project_comments`, `value_lens.notifications`에 독립된 행으로 저장한다. 댓글은 기존 조직 JSON 1MiB 한도에 포함하지 않는다. 기존 업무·실적·보고서 JSON 구조와 한도는 유지된다.
- RLS와 서버 전용 역할을 사용하고 anon/authenticated의 직접 테이블 읽기는 허용하지 않는다. 서버 API가 현재 조직 소속, 프로젝트 배정, 쓰기 권한을 검사한다. 알림 개수·목록·읽음 처리에도 같은 접근 조건을 적용한다.
- 읽기 권한 구성원과 보관된 프로젝트는 읽기만 허용한다. 완료 프로젝트에는 사후 의견을 남길 수 있다. 외부 프로젝트 항목이나 배정되지 않은 구성원에 대한 확인 요청은 거부한다.
- 댓글 생성은 UUID로 재시도 중복을 막고, 수정은 버전 비교로 충돌을 감지한다. 업무 저장과 알림 생성은 같은 DB 트랜잭션에 포함한다. 실패한 저장에는 알림을 만들지 않는다.
- 댓글/알림은 한 번에 50개씩 조회한다. 댓글은 3,000자, 작성자당 조직 내 분당 20개, 수정 최대 25회다. 알림은 새 이벤트부터 생성하며 과거 업무 전체의 알림을 소급 생성하지 않는다.
- 기존 실적에 작성자 정보가 없는 경우 프로젝트 담당자에게 검토 결과를 알린다. 새 실적의 작성자는 서버에서 기록한다.
- CLI로 생성한 마이그레이션: `20261006062354_project_collaboration.sql`. 운영 Supabase 적용 및 앱 이력 체크섬 기록 완료. 새 환경변수는 없다.

## 검증

- 전체 회귀 **113/113**, 타입 검사 통과. 마지막 경량 조회·오류 처리 수정 후 관련 서버 테스트 4개 재통과.
- 두 독립 테스트 브라우저에서 담당 업무 배정 → 구성원 알림 → 항목 댓글/확인 요청 → 관리자 답변 → 약 24.4초 후 자동 표시를 검증했다. 새 업무가 생겨도 작성 중 문구는 유지되고, 작성 종료 후 새 버전을 반영했다.
- 실제 React UI·서버 핸들러·PostgreSQL PGlite를 사용하고 로그인 신원은 합성 계정으로 주입했다. 실제 운영 사용자 세션을 사용한 인수 검증과 구분한다. JavaScript 오류 0, 모바일 390px 문서 및 알림 대화상자 가로 넘침 0.
- 운영 테이블 RLS, 서버 역할/시퀀스 접근, 브라우저 역할의 직접 조회 차단을 확인했다. Advisor에서 새 테이블의 권한 누락이나 FK 인덱스 누락은 없었다. 새 인덱스는 아직 사용 이력이 없다는 정보가 표시된다.
- 공유 프로젝트의 기존 [RLS 무정책 정보](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [비밀번호 유출 방지 설정 경고](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection), 기존 테이블의 [FK 인덱스 정보](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys)는 별도 운영 항목이다. 다른 앱의 스키마나 공유 Auth 설정을 변경하지 않았다.
