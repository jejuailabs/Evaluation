# 문서에서 목표 설계로 이어지는 흐름과 보고서 출력

2026-10-06 · v0.4. 기존 연간 운영 설계를 유지하고 문서 입력·목표 설계·보고서 출력 구간을 확장했습니다.

## 이번에 실제 연결한 흐름

자료함 / 프로젝트 자료·기록 → 여러 원본 등록 → 버전별 내용 열기 → 문단·셀·페이지 위치 확인 → 원문으로 지표 설계 → 담당자 대조 확인 → 목표·예상 저장 → 기존 현장 실적 검토 → 연간 목표와 기간 보고 → Word·Excel·웹 문서 출력.

설계 원문을 실적 근거와 구분합니다. 문서에서 지표를 만든 것만으로 실적이나 달성률을 만들지 않습니다. 지표에 원본 문서·버전·위치·발췌·직접/AI 방식·검토 시각을 저장합니다. 새 문서 버전을 올려도 이전 지표와 보고서는 당시 원본 버전을 유지합니다.

## 문서 읽기 범위

| 형식 | 구현 범위 | 포함하지 않는 것 |
|---|---|---|
| HWPX | 구역·문단 순서와 표 안 본문 텍스트 | HWP 바이너리, 사진·도형·머리말·주석·원래 배치 |
| DOCX | 본문 문단·표의 텍스트, 삭제 추적 텍스트 제외 | 사진·도형·머리말·주석·원래 배치 |
| XLSX | 시트명·행·셀 주소, 공유 문자열, 저장된 숫자/수식 결과 | 수식 실행·재계산·날짜 표시 서식. 숨긴 셀도 포함 |
| PDF | 디지털 텍스트와 페이지·행 위치 | 스캔 OCR, 이미지 분석, 원래 표 배치 |
| TXT/MD/CSV/TSV/JSON/LOG | 행별 텍스트, UTF-8 및 EUC-KR 대체 읽기 | CSV 타입 추론이나 자동 실적 등록 |

원본은 파일당 25MiB, 한 번에 12개까지 등록합니다. 등록 성공 파일은 재시도하지 않고 실패 파일만 다시 처리합니다. 저장은 최신 조직 revision을 사용합니다. 추출은 브라우저 안에서 수행하며 원문 전체를 조직 JSON에 복제하지 않습니다. 일반 문서 추출은 별도 Worker에서 15초 제한, ZIP 내부 2,000개 파일·텍스트 XML 실제 해제량 12MiB 제한, 외부 엔티티/손상 XML 차단을 적용합니다. PDF는 25초·앞 80쪽, 결과는 8만 자·1,500개 블록까지 표시합니다. 한도와 누락 가능성을 사용자에게 표시합니다.

## AI 초안 연결 코드와 현재 운영 상태

- 서버의 `OPENAI_API_KEY`와 `OPENAI_MODEL`이 모두 있어야 활성화합니다. 키는 브라우저·저장소·채팅에 넣지 않습니다.
- 관리자만 자신의 조직에 등록된 문서 버전을 선택해 요청할 수 있습니다. 선택 블록 80개·3만 자, 조직당 최근 24시간 20회로 제한합니다. 유료 요청 전에 DB에 원자적으로 호출 슬롯을 확보합니다. 실패도 호출 수에 포함됩니다.
- 선택 문장과 프로젝트 이름·목적을 OpenAI Responses API에 보냅니다. 화면에서 전송 범위를 안내하고 사용자가 실행합니다. `store:false`, 구조화 출력, 45초 제한을 적용합니다.
- 문서 안의 지시는 실행하지 않습니다. 제공한 원문에 없는 인용, 알 수 없는 참고 기준, 잘못된 비율과 정성 수치를 거부합니다. 원문 발췌는 브라우저가 보내는 데이터이며 서버에서 원본 파일과 다시 대조하는 파이프라인은 아직 아닙니다. 최종 원문 대조는 담당자가 수행합니다.
- AI는 초안만 반환합니다. 수치·정의·중복 제외 방법과 기준을 사람이 수정·확인한 다음 기존 `indicator.add` 권한·검증을 거쳐 확정합니다. 지표·실적을 자동 생성하지 않습니다.
- **현재 운영 환경에는 키와 모델 설정이 없습니다. 실제 유료 모델 호출을 완료했다고 간주하지 않습니다.** OpenAI Developers 플러그인도 미설치 상태를 확인했습니다. 연결 후 실제 문서 품질·민감정보·비용·오류 인수가 남아 있습니다.
- Google/Supabase 인증도 기존 준비 코드 상태이며 운영 설정은 아직 비어 있습니다. 실제 DB는 D1, 원본은 R2입니다.

## 보고서 형식

- **DOCX:** 편집 가능한 실제 OOXML Word 문서. 기간·목적·목표/예상/확인값·정성 기준·예산·정의·설계 원문·실적 버전·현장 기록·해석·집계 주의 사항을 포함합니다.
- **XLSX:** 실제 Excel 통합 문서. 보고 개요, 연간 목표, 프로젝트 지표, 설계/실적 근거, 사업비, 분기 점검 또는 현장 기록/원본 목록을 나눕니다. 수치는 숫자 셀, 미입력은 빈 셀입니다. 사용자 문자열은 인라인 문자열로 저장해 수식으로 실행하지 않습니다. 수식은 생성하지 않습니다.
- **HTML:** 기존 독립 보고서에 설계 근거를 추가합니다. 연간 집행 차트와 보고 당시 수치를 유지합니다.
- **PDF:** 별도 PDF 변환 서버가 아니라, HTML 보고서의 브라우저 인쇄 창에서 PDF 저장을 선택하는 방식입니다.
- 내려받기는 생성 후 다시 받기 링크도 제공합니다. 파일 형식이나 보고서를 바꾸면 이전 링크를 해제합니다.

기관별 지정 HWPX 서식 출력, 사진 자동 배치, 결재·제출·증빙 묶음은 이번 범위에 포함하지 않았습니다. 기존 보고서는 저장 당시 내용만 내보내며 나중에 추가된 설계 근거를 과거 스냅샷에 끼워 넣지 않습니다.

## 다음 개발 우선순위

1. **실서비스 연결:** 사용할 Supabase 프로젝트 확정과 Google 공급자 설정·두 계정 인수, OpenAI Developers 연결과 비밀 설정·실제 문서 분석 품질 검증.
2. **협업과 집행:** 프로젝트 댓글·알림·재원/세목 배정·결재·보완·수정/취소·부분 지급·정산.
3. **자료 활용:** 사진/녹음 미리보기, OCR·STT·TTS, 미분류함·검색 색인·문서 비교·복원.
4. **제출 서식:** 실제 제출 양식 확보 → 필드 매핑 → HWPX/DOCX 템플릿 보존 출력 → 검토/승인·증빙 묶음.
5. **연간 운영 규모:** 조직 JSON 1MiB 구조를 테이블·첨부/보고 스냅샷 저장으로 분리, 페이지 조회·백업/복원·감사/부하 검증. 전체 운영 출시 완료를 선언하지 않습니다.
