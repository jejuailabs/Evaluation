## 데이터와 실행 규칙

참조 문서를 연결해도 원본 프로젝트 접근 권한이 생기지 않는다. 증빙으로 사용 중인 참조는 해제할 수 없다. 복원은 기존 버전을 삭제하지 않는다. 참여자는 이름·연락처 대신 조직 내 무작위 식별 코드를 입력하고 브라우저에서 해시하며, 동일 코드는 같은 조직 안에서만 중복 집계하지 않는다.

이월은 전년도 계획/배정에서 같은 금액을 차감하여 다음 연도에 더한다. 이월한 예정·검토 요청은 새 연도에서 다시 승인한다. 이미 승인한 미지급금은 원래 집행일을 유지하고 지급 원장에 실제 지급일을 기록한다. 결재선과 직무 분리는 검토 요청 당시 규칙을 보존한다.

제출 파일은 원본 해시와 보고서 버전을 함께 저장한다. 앱 DB 역할은 제출 파일/기관 양식 기록을 수정·삭제할 수 없다. 새 양식은 새 버전으로 저장한다. 제출 버튼은 담당자가 수행한 외부 제출의 기록이며 외부 기관으로 전송하지 않는다.

## 명시된 처리 한도

- 파일당 25MiB, 조직 저장 500MiB. 음성 전사는 공급자 기준 25,000,000바이트, 백그라운드 결과 120,000자까지다. TTS는 6,000자까지다.
- 작업 생성은 조직당 24시간 40건, 한 실행 최대 110초 임대, 실패 시 2분 후 최대 3회 자동 시도. 결과 공개 직전에도 조직/작성/프로젝트 권한을 다시 검사한다.
- HWPX/DOCX/XLSX/PDF/텍스트를 읽는다. PDF는 80페이지, 본문은 80,000자·1,500문단 한도이며 초과 경고를 표시한다. 암호·손상·지원하지 않는 형식은 원본을 보관하고 실패 이유를 표시한다. 변환은 본문 텍스트 변환이다.
- 파일 검사는 실행 파일·매크로·EICAR·압축 경로/파일 수/해제 용량을 검사한다. 상용 안티바이러스 전체 서명 검사를 대신한다고 표시하지 않는다.
- 기관 양식은 텍스트 입력 자리를 연결하고 기존 레이아웃을 유지한다. 표는 기본 HWPX 보고서에, 차트·사진·근거는 ZIP의 HTML 보고서와 원본 목록에 포함한다. 묶음 원본 합계는 40MiB까지다.

## 운영 설정과 실행 명령

`20261006131547_finish_workspace_workflows.sql`은 운영 DB에 적용했다. `WORKER_SECRET`은 서버에만 두며 클라이언트로 보내지 않는다.

운영 예약 활성화는 자동 승인 검토가 명시적 승인을 요구하여 대기 중이다. 승인 대상은 `20261006140847_configure_background_worker.sql`의 제한된 설정 함수와 `scripts/configure-worker.ts` 실행이다. 이 앱 전용 Vault 비밀키 및 `value-lens-worker` 작업만 설정하고, 대기 작업이 있을 때 매분과 기한 알림을 위해 매시간 `https://evaluation-five-xi.vercel.app/api/internal/worker`를 호출한다. 승인 전에는 예약 실행이 활성화됐다고 판정하지 않는다.

전체 관리자 화면과 서버 ID 허용 목록은 구현되어 있다. 실제 지정할 로그인 계정은 사용자 확인을 요청했다. 확인되지 않은 계정에 전체 조직 제어 권한을 임의 부여하지 않는다.

```powershell
node --env-file=.env.local --import tsx scripts/backup-workspace.ts create
node --import tsx scripts/backup-workspace.ts verify .sites-runtime/backups/<backup>.backup
node --env-file=.env.local --import tsx scripts/configure-worker.ts
```

백업과 키는 Git 제외 `.sites-runtime/backups`에 분리 저장된다. 마지막 설정 명령은 운영 승인 및 마이그레이션 적용 후 실행한다. 복원 검증은 별도 DB에서 실행되며 운영 데이터를 덮어쓰지 않는다.
