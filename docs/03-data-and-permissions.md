# 03. 데이터·권한·버전

상태: 설계 기준 v0.1 · 2026-10-05. 아래는 운영 서비스 목표 모델이다. 계정·조직·권한의 1차 서버 구현과 한도는 [06 문서](06-accounts-and-admin.md)를 함께 읽는다.

## 연결의 기본 단위

모든 업무 데이터는 조직 ID에 속한다. 프로젝트는 조직의 하위 단위이며 여러 팀·사용자가 참여한다. 전역 사용자 ID와 조직 내 멤버 ID를 분리한다. 조직 이동이 데이터 이동이나 자동 권한 이전을 뜻하지 않는다.

| 영역 | 주요 엔터티 | 관계와 유지할 규칙 |
| --- | --- | --- |
| 조직 | Organization, User, Membership, Team, ProjectMembership | 조직 역할 + 프로젝트 역할, 초대·활성·정지·탈퇴 |
| 운영 | Project, Task, TaskDependency, Schedule, Decision, Comment | 업무마다 프로젝트·책임자·기한, 상호 의존 순환 금지 |
| 자료 | Document, DocumentVersion, Record, EvidenceLink | 논리 문서와 불변 파일 버전 분리, 레코드는 원문 버전을 참조 |
| 예산 | FundingSource, BudgetVersion, BudgetLine, Commitment, Expense, Payment, Allocation | 금액·상태·재원·귀속·지급을 분리, 이중 계산 금지 |
| 성과 | IndicatorDefinitionVersion, ProjectIndicatorVersion, Forecast, Measurement, Review | 정의·목표·예상·관측값·검토 분리 |
| 보고 | TemplateVersion, ReportSnapshot, Submission | 기간·정의·목표·확인실적·증빙·출력 버전 고정 |
| 공통 | Approval, AuditEvent, Notification, Job | 처리자·대상 버전·시간·이유·재시도/실패 이력 |

문서 원본 하나를 여러 프로젝트가 참조할 수 있지만 접근 권한을 넓혀서는 안 된다. 원문이 제한되면 추출 텍스트·요약·임베딩·미리보기·보고서도 해당 범위의 권한을 따른다.

## 수집·원본·추출 데이터의 분리

- `Record`: 자유 텍스트, 실제 활동일, 작성자, 분류, 프로젝트/조직 공통 범위, 공개 범위, 검토 상태를 가진 기록. 첨부가 없는 글도 유효하다.
- `RecordAttachment`: 하나의 기록에 여러 `DocumentVersion`을 연결. 같은 원본을 여러 기록이 참조할 수 있다.
- 파일 저장소: 음성·이미지·HWPX·엑셀 등 바이너리 원본과 파생 파일. 일반 관계형 DB에 대용량 파일 본문을 모두 넣지 않는다.
- 관계형 DB: 기록, 파일 메타데이터, 버전, 권한, 프로젝트·업무·지표 연결과 확정 수치.
- `ExtractionRun`/`ExtractedBlock`: 원본 버전과 도구 버전에 따른 문단·표·시트/셀·페이지·타임코드. 추출 결과는 원본의 대체물이 아니다.
- 검색 인덱스/임베딩: 재생성 가능한 파생 데이터. 원본 권한·삭제·새 버전 상태를 반영한다.
- `ClassificationProposal`: 프로젝트·종류·업무·지표 연결 제안. 확인 전 임의 재분류/공개/실적 반영 금지.

조직 공통/미분류 기록은 프로젝트 ID가 없을 수 있다. 최종 운영 모델에서는 명시적인 조직 범위와 접근 정책을 가진다. 프로젝트를 분류하기 전까지 기본 접근은 작성자와 지정 수집 담당자에게만 부여한다. 시제품은 안전한 단순화를 위해 모든 업로드에 프로젝트를 선택하도록 한다.

수집 예: 음성+사진+엑셀을 하나의 현장 기록에 첨부 → 원본 저장 → 각각의 추출 작업 → 동일 기록 맥락에서 활동/참여/비용 후보 제안 → 담당 확인 → 지표와 예산의 참조 연결 → 보고서. 실패한 추출 작업만 재시도하고 성공한 원본을 다시 올리게 하지 않는다.

## 서버 경계

- 인증된 사용자로부터 조직 멤버십을 조회한다. 브라우저가 보낸 orgId만 신뢰하지 않는다.
- 모든 읽기/쓰기/집계/파일 URL 발급/백그라운드 작업/AI 검색에 조직·프로젝트 범위를 검사한다.
- 조직과 프로젝트가 일치하는 복합 참조 제약 및 교차 조직 회귀 테스트를 둔다.
- 파일은 비공개 객체 저장소에 저장하고 권한 확인 후 짧은 만료 URL을 발급한다.
- 원본 업로드 → 검증·격리 → 추출/변환 → 검색 등록은 작업 큐로 분리한다. 실패해도 원본은 유지한다.
- 변경 명령은 idempotency key, expected revision을 받아 중복 집행·중복 업로드 및 덮어쓰기를 방지한다.
- 금액은 통화별 최소 단위의 정수, 날짜는 조직 시간대의 업무 날짜, 처리 시각은 UTC를 사용한다.

## 권한 기준

| 행동 | 조직 관리자 | 프로젝트 책임자 | 담당자 | 회계 역할 | 검토 역할 | 외부 협력자 |
| --- | --- | --- | --- | --- | --- | --- |
| 조직 설정·초대 | 허용 | 위임 범위 | 불가 | 불가 | 불가 | 불가 |
| 프로젝트 계획·업무 | 조직 범위 | 배정 범위 | 배정/공유 범위 | 조회 범위 | 조회 범위 | 명시된 범위 |
| 원본·기록 등록 | 허용 범위 | 허용 범위 | 허용 범위 | 허용 범위 | 허용 범위 | 요청받은 영역 |
| 지출 신청 | 허용 | 허용 | 허용 | 허용 | 별도 배정 | 기본 불가 |
| 지출 승인·지급 | 위임 기준 | 한도 기준 | 기본 불가 | 결재선 기준 | 불가 | 불가 |
| 지표·실적 확정 | 정책 기준 | 정책 기준 | 기본 불가 | 불가 | 배정 지표 | 명시된 검토 |
| 제출 보고서 확정 | 허용 범위 | 위임 범위 | 불가 | 별도 배정 | 위임 범위 | 불가 |

역할은 조합 가능하다. 조직 관리자라는 이유로 민감한 참여자 원본을 무조건 볼 수 있게 하지 않는다. 기본은 신청자와 승인자 분리이며, 소규모 조직의 자기 승인 예외는 조직 정책·사유·감사 기록을 남긴다.

## 상태 전이

- 업무: 예정 → 진행 → 검토 → 완료. 취소는 이유를 남긴다. 완료 후 재개 이력을 기록한다.
- 문서: 업로드 → 검사 → 사용 가능 / 격리 / 실패. 내용의 초안·검토·확정 상태는 파일 처리 상태와 별도다.
- 지출: 초안 → 신청 → 승인/반려 → 확정 → 부분지급/지급완료. 취소·환불은 상쇄 거래로 처리한다.
- 성과: 입력/AI 제안 → 검토 요청 → 확인/반려. 확인된 값의 수정은 새 버전, 이전 값의 효력을 명시적으로 대체한다.
- 보고서: 초안 → 검토 → 확정 → 제출. 제출 이후 변경은 정정본으로 생성한다.

전이마다 행위자 권한, 필수 증빙, 예상 버전, 이전 상태를 검증한다. 화면에서 버튼을 숨기는 것만으로 구현하지 않는다.

## 버전 규칙

원본과 승인 이력은 덮어쓰지 않는다. 복원은 과거 내용을 가져온 새 버전이다. 파일 해시·파일명·형식·크기·등록자·시각을 보존한다. 동일 내용/다른 이름 중복은 제안만 하고 임의 병합하지 않는다.

목표·예산·지표 정의 변경은 기존 버전과의 차이 및 사유·승인을 남긴다. 지표 정의가 달라지면 이전 관측값을 그대로 새 정의로 집계하지 않는다. 원문이 갱신되면 관련 추출·실적·보고서에 ‘재확인 필요’를 표시한다. 자동으로 확정 값을 바꾸지 않는다.

제출 보고서는 참조 ID뿐 아니라 당시 렌더링에 필요한 값·정의·차트 입력·출처 버전·템플릿 버전도 저장한다. 참조 문서 접근권이 없어져도 보고서 접근권에 따른 노출 정책을 별도로 적용한다.

## 예산 계산

- 확정 집행 = 승인되어 비용으로 확정된 금액. 지급 여부와 다르다.
- 약정 잔액 = 확정한 약정 중 아직 집행으로 전환되지 않은 금액.
- 사용 가능 = 배정 예산 − 확정 집행 − 약정 잔액.
- 미지급 = 확정 집행 − 지급 누계. 환불/정정과 통화를 고려한다.
- 담당자별 집행은 신청자·비용 귀속 담당자·승인자·지급자를 구분해서 조회한다.
- 기간별 집행은 비용 귀속일, 지급은 지급일 기준을 사용하며 화면에 기준을 표시한다.
- 프로젝트 총예산과 예산 항목 합계, 원거래와 재원·프로젝트별 배분 합계가 일치해야 한다.

시제품은 단일 KRW 통화·전체 프로젝트 예산과 상호 배타적인 예정/확정/지급 상태로 축소한다. 부분 지급·약정 전환 이력·분할 배분은 운영 모델 구현 전까지 제공하지 않는다.

## 운영 기술 구조

화면 → 명령/조회 API → 도메인 규칙 → 관계형 데이터베이스. 파일은 객체 저장소, 추출/AI/변환/보고서 생성은 작업 큐. 검색·알림·감사·권한은 공통 기능으로 둔다. 처음에는 모듈별 경계가 있는 하나의 서버로 시작하고, 실제 부하와 배포 필요가 확인될 때 분리한다.

개인정보 최소 수집, 기록/보존 정책, 삭제·법정 보존 예외, 백업·복구 연습, 관측/오류 추적, 조직별 사용량·AI 비용 한도는 운영 출시 전에 검증한다. 법적 보존기간은 고객 계약·업무와 관련 기준을 별도로 검토해 결정한다.
